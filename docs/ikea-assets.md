## Asset package

Each configuration ships as `public/models/interior/<id>.glb`, `<id>-mobile.glb` and `<id>.png`. Both GLBs embed original textures and normalize actual vertex bounds to the reference envelope. The automated audit reads the files, validates dimensions within 0.1 mm, checks floor-centred origins, compares triangle counts and confirms PNG thumbnails. Footprints use conservative rotated outer rectangles.

All geometry, textile maps and thumbnails were independently authored; original asset files are CC0-1.0. Models describe recognizable construction, cushions, legs, shelves, handles, chair backs and lamp shapes with modest geometric detail. The generated package does not contain downloaded manufacturer preview models or photography. The [manifest](../public/models/interior/manifest.json) includes per-file bytes/triangles/bounds, author, provenance and product references. [Attribution](../public/models/interior/ATTRIBUTIONS.md) records redistribution terms. Existing room-finish scan sources remain in [texture attribution](../public/textures/README.md).

## Rebuild

1. Run `npm ci` with Node 22.12+ and `npm run dev:interior`.
2. Optional texture regeneration: Python 3 with Pillow, `python scripts/build_textiles.py --help`; checked-in source PNGs normally suffice.
3. Run `npm run assets:interior` for geometry and the manifest.
4. Run `npm run assets:thumbnails` with the server on port 5187 and Chrome installed. Use `-- --url <origin>` for another isolated origin.
5. Run `npm test -- src/interior/assets.test.ts` and inspect the asset contact sheet in `output/interior-editor/`.

On-demand GLTF loading shares cached geometry, textures and materials among repeated instances. Mobile layouts choose the lighter GLB. Load failure retains an accurately sized, selectable fallback and a visible retry button. Texture embeddings are small (256 px); textures within repeated models are shared, while different GLB files each carry their own embedded maps.

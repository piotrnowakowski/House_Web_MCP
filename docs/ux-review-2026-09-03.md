# UX review of the ProjectV2 spatial editor

Date: 2026-09-03 · Branch reviewed: `feature/ux-review` (single mode + texture library) · Reviewer: Claude Code session with the owner

## Method

- Ran the app in installed Chrome 152 with the WebMCP flags and captured sixteen states at 1440, 1280, 834 and 390 px: initial load, wall selected, zone selected, every panel, the approval dialog, the sun-hours overlay and keyboard focus.
- Ran a DOM audit on the live page: element sizes, accessible names, font-size histogram, z-index values, landmarks, reduced-motion and focus-visible coverage.
- Measured text contrast for the eighteen colour pairs used for captions, hints and labels.
- Checked the UI/UX Pro Max guideline database (accessibility, touch, feedback, animation, web interface, React). Its generated visual style (landing-page pattern, Cinzel and Josefin fonts) is not applicable to an editor and was set aside; the guideline rules were applied.
- Looked at comparable products on Mobbin for editor layouts, material pickers, AI-suggestion review and onboarding tours, and at the ARIA Authoring Practices (dialog, toolbar), drei (`useProgress`) and react-three-a11y docs through Context7.

## Summary

The editor is functionally rich and consistent in its dark palette, every control carries an accessible name, reduced motion is respected and the status region announces changes. The problems are concentrated in four places: text that is too small and too faint to read, overlays that collide (toast over the sun widget, scene labels over panels, the approval dialog over the ghost it asks you to review), a review flow that hides the change it wants approved, and an inspector that stacks four editors above the model tree with no way back. Most P0 items are CSS or attribute fixes; the review flow and inspector need design work.

Scorecard (1 poor, 5 strong):

| Area | Score | Main reason |
| --- | --- | --- |
| Accessibility | 2 | 6 to 9 px captions, eight colour pairs under 4.5:1, browser-default focus ring on near-black, no dialog semantics |
| Layout and overlays | 2 | Toast covers the sun widget, scene labels leak above panels, approval dialog covers the viewport centre |
| Feedback and undo | 3 | Good status toasts, but success and error look the same, undo only via a shortcut, no redo |
| Information architecture | 3 | Clear top bar, but wall selection pushes four editors above the model tree, jargon leads |
| Review flow (proposals) | 2 | Dialog hides the ghost, no before/after, no per-operation highlight, tiny status badges |
| Onboarding and empty states | 2 | No first-run guidance; the inspector tells you what to select but not how |
| Visual consistency | 4 | Coherent palette, spacing and card language across panels |

## Relation to the owner's open PR #4

PR #4 (`codex/garden-editor-improvements`, open while this review was written) adds `src/accessibility.css` with a readability floor (12 px body and controls, 10 to 11 px labels, applied with `!important`), scrollbar styling, an outdoor furniture library, movable zones and unlockable plants, and it removes the Section viewer mode. That covers part of finding 3 and the Section mention in finding 12. Findings 1, 2, 4, 5 and 6 are untouched by it. PR A below should replace the `!important` floor with the token-based type scale once #4 has merged, and the measurements in this document should be retaken on the merged result.

## Findings

Severity: P0 fix now, P1 next sprint, P2 later. Effort: S under half a day, M one to two days, L three days or more.

### P0

1. **The toast covers the sun widget's action row.** Evidence: initial-load and sun-hours captures; the toast sits bottom-left over "Play day, Play year, Sun hours" and over the sun-hours legend. Fix (S): move the toast to bottom-centre above the navigation hint, or top-centre under the toolbar; reserve space so nothing shifts.
2. **Scene labels render above panels.** The sun-path tick "20:00" and the entrance label show over the MCP search box, the soil analysis heading and the land legend. Cause: drei `Html` assigns z-index values above fifteen million while panels use 40 to 44. Fix (S): pass `zIndexRange={[9, 0]}` to every `Html` and hide editor-only labels while a panel or dialog is open.
3. **Text is too small.** Font-size histogram on the initial screen: 6 px on four elements (proposal badges), 8 px on eleven, 9 px on forty-two, 10 px on twenty-three. Guideline minimum is 11 px for captions and 12 to 13 px for controls. Fix (M): a type scale of 11, 12, 13, 14, 17 and 20 px as CSS variables; retire the monospace micro-captions or lift them to 11 px.
4. **Eight caption colours fail 4.5:1.** Measured against the panel background: placeholder 2.9:1, proposal timestamps 3.2:1, tool count 3.5:1, fixture captions 3.7:1, finish captions 3.8:1, opening note 3.95:1, model-tree captions 4.3:1, climate ticks 4.35:1. Fix (S): two muted tokens, `#8a968f` (5.7:1) for 11 px and up, `#9aa79f` (7:1) for anything smaller that survives item 3.
5. **Keyboard focus is nearly invisible.** Only six selectors define `:focus-visible`; everything else shows the browser's 1 px blue ring on near-black (measured on the "Plan" button). Fix (S): one global rule, `:focus-visible { outline: 2px solid #8bd8c9; outline-offset: 2px }`, plus an inset variant for list rows.
6. **The approval dialog is not a dialog and hides what it asks you to review.** It has no `role="dialog"`, no `aria-modal`, no initial focus, no focus trap and Escape does not act on it; there is no scrim, so the canvas stays clickable. It is centred over the viewport where the translucent ghost renders. Fix (M): follow the ARIA modal-dialog pattern for semantics, and dock the review to a bottom bar or the inspector so the ghost stays visible. Add a Before/After toggle and hover-to-highlight per operation using the existing `diffProjects` output. Reference: inline accept/reject with highlighted changes in the [Langdock suggestion flow](https://mobbin.com/flows/23c25e1d-38d3-4baa-a18b-f5e8cf27e110) and the [Semrush AI editing flow](https://mobbin.com/flows/65a35cc7-6476-4cd8-a69e-8a7e568a12da).

### P1

7. **Two apply models.** A zone scan applies at once with undo; a wall scan waits for "Apply to this wall" and shows no preview. Fix (M): preview the wall pick live on the selected wall and keep the explicit Apply for scope, or apply at once for both. [Stitch's theme panel](https://mobbin.com/screens/3f8dcbb9-376d-4aff-8d5e-3ff1152b5bd9) uses "Save" and "Save & Apply" to make the two scopes explicit.
8. **Undo is hidden and there is no redo.** Undo exists only as Ctrl+Z mentioned in toasts; the store keeps forty history entries but no redo stack. Fix (M): Undo and Redo buttons in the top bar with tooltips and a disabled state, and a redo stack in the store.
9. **Proposal badges are unreadable.** "P 0 A 0 R 0 S 0" at 6 px. Fix (S): one pending count that turns lime when above zero, and the breakdown in the tooltip and `aria-label`.
10. **Primary action hierarchy.** "Architectural set" is the only filled button in the top bar, yet report generation is a secondary task. Fix (S): move it into a Reports menu next to MCP Tools; let the pending-proposal count be the attention-grabbing element.
11. **Inspector stacks too much.** Selecting a wall shows wall finish, façade layout, fine controls and then the full model tree, with no breadcrumb or deselect. Wall names such as "Wall 1" and "Wall 5" leak through. Fix (L): Object and Scene tabs in the inspector (compare Object, Camera and World in [Krea AI's editor](https://mobbin.com/screens/26034a96-934d-4a5c-bd25-06d3af820c5a)), a sticky header with the object name, its ref as a secondary copyable line and a close button; friendly generated names.
12. **Viewer-mode toolbar.** Text-only buttons with native `title` tooltips, no icons, no shortcut keys, no `role="toolbar"` or roving tabindex; Plan mode picks the first storey with no storey indicator. Fix (M): toolbar semantics with arrow-key movement, icons with labels, shortcut hints (E, L, A, H, S, P) and a storey switcher in plan mode.
13. **No onboarding.** The inspector says what can be selected but not how; the navigation hint covers movement only. Fix (M): a three-step coach-mark tour (select the courtyard wall, pick a scan, review a proposal) with "I'll explore myself", stored in `localStorage`, following [Canva's guided tour](https://mobbin.com/flows/d3237fe5-9e7c-47ec-89e6-56ccfd951dc1) and [Pitch's welcome tour](https://mobbin.com/flows/c4802559-194c-49aa-af85-c81255874ab9).
14. **Loading has no state.** The viewport shows flat grey while the worker meshes and textures load; the only signal is a toast after the fact. Fix (S): drei `useProgress` in a small progress pill and a skeleton in the inspector.
15. **Sun widget details.** The slider announces "14.25" instead of "14:15" (no `aria-valuetext`); there are no markers for sunrise, noon and sunset on the track and no "Now" or "Noon" shortcuts; the day input accepts values beyond the month. Range sliders with labelled endpoints in [Clockwise](https://mobbin.com/screens/d925c872-b650-4c4f-a731-e9357d9dd1bd) and [Mindtrip](https://mobbin.com/screens/b2b41458-9948-4023-b45a-7715f0054ec3) show the pattern. Fix (S).
16. **Small screens.** `body { min-width: 1024px }` with no message; at 834 px the inspector is cut off and the page scrolls horizontally, at 390 px it is unusable. Fix (M): a drawer inspector from 768 px, or at least a "best on a laptop" notice under 1024 px.
17. **Panels are windows without semantics.** Climate, Planting, MCP Tools, Proposals and Report open as overlays with no `role="dialog"`, focus stays behind them, and the global Escape handler also clears the selection and viewer mode. Fix (M): dialog semantics with focus return, and an Escape handler scoped to the topmost layer.
18. **Toasts.** Success and error look identical (same lime border), a second toast replaces the first, errors auto-dismiss in 4.2 s. Fix (S): error and success variants with an icon, a short queue, persistent errors with a dismiss button.
19. **Jargon leads.** "PROJECTV2 / SEMANTIC MODEL", "ghost variant", "r1" and refs like `wall/courtyard-living` appear before plain names. Fix (S): plain names first, refs as a secondary line with a copy action, "proposal preview" instead of "ghost variant" in user-facing copy.

### P2

20. **3D objects are not keyboard reachable.** The canvas is focusable with `role="application"`, but walls and zones can only be selected with a pointer or through the model tree. react-three-a11y's `A11y` wrapper with `A11yAnnouncer` would make key objects focusable and announced.
21. **Texture picker polish.** Names wrap to two lines at 9 px, the default is marked with a text suffix rather than a badge, and single-select buttons use `aria-pressed` where a radio group (`role="radiogroup"`, `aria-checked`, arrow keys) fits better. [Squarespace's background picker](https://mobbin.com/screens/925db63b-74b6-4961-8fd2-a5ec511d1733) shows hover actions on tiles.
22. **Hover states shift layout.** Fixture rows and tool list rows translate 2 to 3 px on hover; use colour or border changes instead.
23. **No z-index scale.** Values in use: 4, 10, 11, 12, 13, 20, 40, 42, 44, 50, 60, plus the drei values. Declare tokens and use them.
24. **Delete confirmation popover** is absolutely positioned and can overflow the inspector bottom; render it inline.
25. **Heading hierarchy.** No `h1`; the page title is "ProjectV2 Spatial Editor". Add a visually hidden `h1` and keep panel headings at `h2`.

## What already works well

- Every one of the 42 interactive elements has an accessible name; the status toast is a live region; reduced motion is honoured for animations and the sun playback.
- Escape and Ctrl+Z work everywhere; the opening editor, façade presets and scan pickers give immediate feedback.
- The proposal model (ghost, approve or reject, history) is a strong foundation; the review UI is what needs work, not the model.
- The dark palette, card language and spacing are consistent across panels.
